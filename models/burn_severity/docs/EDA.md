# BS — EDA

Модуль 2: картирование гарей и степени поражения. Скрипты — `eda/eda.py`,
`eda/rule_variants.py`, запускаются из корня проекта, работают ~15 секунд.

---

## 1. Задача и метрика

**Вход:** BS-чип 512×512 на сетке 20 м (10.2×10.2 км): Sentinel-2 до и после
пожара, Sentinel-1 до и после, рельеф и тип покрова.

**Выход:** маска 0–3 — не горело, слабая, средняя, сильная степень.

**Метрика:** в итоговый `Score` модуль даёт два слагаемых:

```
Score = 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev
```

- `IoU_burn` — IoU бинарной маски «гарь / не гарь» (классы 1–3 против 0), **вес 0.35**;
- `mIoU_sev` — среднее IoU трёх классов степени, **вес 0.30**.

Контур гари весит больше, чем степень. Текущее решение считает только `mIoU_sev`.

---

## 2. Данные

224 обучающих чипа, 89 тестовых.

| файл | каналы | тип |
|---|---|---|
| `sentinel2_pre`, `sentinel2_post` | B2, B3, B4, B5, B6, B7, B8A, B11, B12, SCL | uint16, отражение ×10000 |
| `sentinel1_pre`, `sentinel1_post` | VV, VH | int16, дБ ×100 |
| `aux` | dem, slope, landcover | int16 |
| `masks` | severity | uint8, nodata 255 |

Папки `pre/`, `post/`, `sar_pre/`, `sar_post/` пустые — данные лежат в
`sentinel2_*` и `sentinel1_*`. В `aux` нет экспозиции склона, хотя постановка
её обещает.

### Метаданные

`fire_event_id` **заполнен** — 224 уникальных значения, по одному чипу на пожар.
Чипы территориально не пересекаются (0 пар с перекрытием), координаты у всех
разные. Значит группировка по чипу — честная валидация без утечки.

| показатель | значение |
|---|---|
| интервал между снимками до и после | 10–50 дней, медиана 15 |
| годы | 2019: 11, 2020: 71, 2021: 11, 2022: 31, 2023: 18, 2024: 82 |
| облачность чипа | медиана 1.3 %, максимум 48.5 % |
| доля валидных пикселей | минимум 51.5 % |

## 5. Главная находка: степень поражения — формула

На стр. 8 постановки (рисунок 6) опубликованы пороги dNBR, по которым строилась
эталонная разметка:

| покров | слабая от | средняя от | сильная от |
|---|---|---|---|
| лес, кустарник (10, 20) | 0.100 | 0.270 | 0.660 |
| травы (30) | 0.062 | 0.204 | 0.386 |
| пашня (40) | 0.070 | 0.177 | 0.380 |
| болото, пойма (90) | 0.075 | 0.331 | 0.677 |

`dNBR = NBR_pre − NBR_post`, `NBR = (B8A − B12) / (B8A + B12)`.

### Проверка на данных

Правило применено к каждому пикселю, сравнение с эталоном.

**Внутри истинного контура гари правило угадывает класс в 92.47 % пикселей.**

```
            правило →   0          1          2          3
эталон 1          78 456  2 151 944    119 797      5 997
эталон 2             850     74 890  2 027 275     88 512
эталон 3               5        179     75 643  1 277 957
```

Ошибки почти только на соседний класс — это границы порогов, а не систематика.

**Вне контура правило бесполезно:** 9.7 млн пикселей фона оно относит к гари.

| метрика, правило на всём чипе | значение |
|---|---|
| IoU_burn | 0.3733 |
| IoU класс 1 / 2 / 3 | 0.246 / 0.401 / 0.596 |
| mIoU_sev | 0.4142 |

Вывод: **эталон = контур гари × правило порогов**. Организаторы взяли контуры
гарей откуда-то извне и внутри них раскрасили степень формулой. Вся трудность
задачи — в контуре.

Подтверждение: из 5.9 млн пикселей гари только 79 тыс. (1.3 %) имеют dNBR ниже
первого порога. Условие «dNBR выше порога» почти необходимо для гари, но далеко
не достаточно — фенология, уборка и вспашка дают тот же сигнал.

### Потолок двухэтапного подхода

Если контур найден идеально, а степень считается правилом:

| класс | IoU |
|---|---|
| 1 | 0.885 |
| 2 | 0.849 |
| 3 | 0.882 |
| **mIoU_sev** | **≈ 0.872** |

Текущее решение — 0.7162 на 4 чипах.

### Уточнение правила

| вариант расчёта dNBR | совпадение внутри гари |
|---|---|
| как есть | 92.47 % |
| **сглаживание каналов 3×3** | **93.33 %** |
| сдвиг −1000 для снимков после 25.01.2022 | 64.74 % |
| сдвиг + сглаживание | 65.65 % |

Гипотеза про сдвиг +1000 в L2A с 2022 года **отвергнута** — данные уже
гармонизированы, правило стабильно по всем годам (91.7–93.8 %), а поправка его
ломает до 38 % для 2022–2024. Сглаживание даёт +0.9 п.п.

## 6. Облака

По слою SCL снимка «после» облаками и тенями закрыто 8.9 млн пикселей, **из них
4.9 % размечены как гарь.** Текущая постобработка зануляет все облачные пиксели
и эти теряет. Облачность из оценки не исключается.

---

## 7. Разбор текущего решения

`current_solution.ipynb`: попиксельный CatBoost, признаки NBR/dNBR/NDVI/dNDVI,
разности радара, окна 5×5, landcover как категория, постобработка — зануление
облаков и медианный фильтр 3×3. Заявлено **mIoU_sev = 0.7162**.

Проблемы:

1. **Обучение на 20 чипах из 224** (`n_chips=20`) и 5 % пикселей.
2. **Валидация на 4 чипах.** Первые 80 % чипов по порядку — обучение, последние —
   проверка. Разброс оценки на 4 чипах огромный, 0.7162 не на что опереться.
3. **`IoU_burn` не считается**, хотя весит 0.35 против 0.30 у `mIoU_sev`.
4. Метрика считается по чипам валидации, а не пулом, как у организаторов.
5. Модель учит степень заново, хотя она почти задана формулой.

---

## 8. Выводы для решения

**Двухэтапная схема, а не многоклассовая модель:**

1. **Бинарная модель контура гари** — вся сложность здесь. Кандидаты — только
   пиксели с dNBR выше порога своего покрова (98.7 % гари там). Задача модели:
   отличить настоящую гарь от уборки, вспашки, засухи, облаков. Ей нужны
   радар, пространственный контекст (гарь — сплошное пятно), NDVI, SCL.
2. **Степень внутри контура — правило организаторов** на сглаженном dNBR
   (93.3 % совпадения), при желании доучиваемое моделью на пограничных пикселях.

Так обе части метрики оптимизируются напрямую: `IoU_burn` первой моделью,
`mIoU_sev` — формулой, которую не надо учить.

**Валидация:** 5 фолдов по чипам (= по пожарам), метрика — пулом пикселей,
оба слагаемых: `IoU_burn` и `mIoU_sev`.
