# Модуль BS — степень поражения гари (CatBoost по dNBR)

Вторая модель команды. По паре снимков Sentinel-2 L2A (до и после пожара) отдаёт
маску `512×512 uint8` с классами `0/1/2/3`: нет гари, слабое, среднее, сильное
поражение. Основан на присланном черновике `fast_basr.ipynb`
(теперь `notebooks/baseline_catboost_bs.ipynb`).

## Содержимое сущности

```text
models/burn_severity/
├── predict.py        # адаптер инференса: load_model() / predict_bs()
├── train.py          # обучение CatBoost, CLI вместо ручной правки путей
├── run_inference.py  # CLI: прогон по тестовым чипам -> results/burn_severity_catboost.csv
├── artifacts/        # baseline_bs_model.cbm (пока пусто — веса не обучены)
├── notebooks/baseline_catboost_bs.ipynb   # исходный черновик + пояснение
└── results/          # сабмишн модуля (появится после первого прогона)
```

## Контракт — такой же, как у AF

```python
from pathlib import Path
from models.burn_severity import WEIGHTS, load_model, predict_bs

model = load_model(WEIGHTS)
mask = predict_bs(Path("…/test/bs/BS_0001"), model)
# numpy.ndarray, uint8, (512, 512), классы 0/1/2/3
```

`predict_bs` принимает либо префикс `<dir>/<chip_id>` (ожидает `_pre.tif` и `_post.tif`),
либо каталог чипа, где ровно одна пара `*_pre.tif` / `*_post.tif`. Перед возвратом
маска проверяется `validate_bs_mask`: размер, тип и допустимые классы.

## Признаки

Попиксельно, три числа на пиксель — ровно как в черновике:

| Признак | Формула |
|---|---|
| `NBR_pre` | `(B8A_pre − B12_pre) / (B8A_pre + B12_pre + 1e-8)` |
| `NBR_post` | `(B8A_post − B12_post) / (B8A_post + B12_post + 1e-8)` |
| `dNBR` | `NBR_pre − NBR_post` |

`B8A` — индекс канала 6, `B12` — индекс 8 (по документации кейса). Один чип даёт
матрицу `262144 × 3`; `NaN`/`inf` обнуляются. Модель — `CatBoostClassifier`,
`loss_function="MultiClass"`, 4 класса, по умолчанию `iterations=150`, `depth=6`,
`learning_rate=0.1`.

## Обучение

```powershell
.venv-bs/Scripts/python.exe -m models.burn_severity.train `
  --data-dir C:/path/to/train --limit 30
```

Чипы ищутся рекурсивно по `*_pre.tif`; разметка — `<chip_id>_mask.tif`
(или `_target.tif`) с классами 0–3. `--pixels-per-chip N` включает подвыборку
пикселей, если полная матрица не помещается в память. Веса сохраняются в
`artifacts/baseline_bs_model.cbm`.

## Инференс

```powershell
.venv-bs/Scripts/python.exe -m models.burn_severity.run_inference `
  --data-dir C:/path/to/test `
  --sample C:/path/to/test/sample_submission.csv
```

Берутся только чипы `BS_*` из шаблона, на каждый пишется ровно три строки —
классы 1, 2, 3. Класс 0 в сабмишн не идёт. Файл проверяется на дубликаты,
пересечения классов и каноничность RLE ещё до записи.

## Сколько это займёт по времени

Замерено на 2 vCPU Intel Xeon 2.8 ГГц, Python 3.11, catboost 1.2.10, rasterio 1.4.4;
синтетические 10-канальные `uint16` GeoTIFF `512×512` со сжатием deflate, модель
`iterations=150, depth=6, MultiClass`; 5 прогонов после прогрева.

| Этап одного чипа | Время |
|---|---|
| Чтение `pre` + `post` (rasterio → float32) | 51 мс |
| Расчёт признаков | 3 мс |
| `CatBoost.predict` на 262144 строках | 130 мс |
| RLE трёх классов | 71 мс |
| **Итого** | **≈ 0,25 с на чип** |

Отсюда полный тестовый прогон: **100 чипов ≈ 25 с, 180 чипов ≈ 46 с** — то есть
меньше минуты на слабой машине, без GPU. Инференс BS узким местом не будет.
Оценка консервативная: RLE замерен на случайной маске (максимум чередований);
на реальных связных контурах он в разы быстрее. Масштабируется линейно по числу
чипов и почти линейно по `iterations`: 300 итераций ≈ удвоение времени предсказания.
Если реальные GeoTIFF окажутся крупнее или без сжатия, вырастет только строка чтения.

Обучение на тех же 2 vCPU: ≈ 31 с на миллион строк, то есть **30 чипов
(7,9 млн строк) ≈ 4 минуты**, 100 чипов ≈ 13 минут. Память: полная матрица
30 чипов в `float64` — около 190 МБ, помещается без подвыборки.

- Веса не обучены: `artifacts/` пуст, `results/` пуст. До первого прогона
