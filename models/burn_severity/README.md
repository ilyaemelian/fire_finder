# Модуль BS — степень поражения гари

По паре снимков Sentinel-2 до и после пожара определяется маска 512×512 с
четырьмя классами: 0 — не горело, 1 — слабое, 2 — среднее, 3 — сильное
поражение. Дополнительно доступны снимки Sentinel-1, рельеф и тип покрова.

**Состояние: переданы весовые коэффициенты и результаты изучения данных.
Расчёт предсказаний пока невозможен — не хватает описания признаков.**
Перечень недостающего приведён ниже.

## Состав

| Путь | Назначение |
|---|---|
| `artifacts/pass1_fold0.ubj` … `pass1_fold4.ubj` | Первый этап: пять моделей XGBoost, по одной на фолд перекрёстной проверки. Бинарная задача, 60 признаков, 800 деревьев каждая |
| `artifacts/pass2.ubj` | Второй этап: XGBoost, бинарная задача, 70 признаков, 800 деревьев |
| `docs/EDA.md` | Изучение данных: баланс классов, тип покрова, облачность, разбор метрики |
| `notebooks/baseline_catboost_bs.ipynb` | Первоначальный черновик на CatBoost, заменён двухэтапной схемой. Оставлен как справочный |
| `results/` | Таблица предсказаний. Пока пуста |

Общий объём весов — 72.7 МБ.

## Замысел решения

Метрика задачи складывается из трёх слагаемых:

```
Score = 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev
```

Модуль BS отвечает за два последних: `IoU_burn` — совпадение бинарного контура
гари, `mIoU_sev` — среднее совпадение трёх классов степени.

Ключевое наблюдение изучения данных: **степень поражения задана формулой, а не
требует обучения.** В постановке опубликованы пороги индекса `dNBR`, по которым
строилась эталонная разметка, причём пороги зависят от типа покрова:

| Покров | Слабое от | Среднее от | Сильное от |
|---|---|---|---|
| Лес, кустарник | 0.100 | 0.270 | 0.660 |
| Травы | 0.062 | 0.204 | 0.386 |
| Пашня | 0.070 | 0.177 | 0.380 |
| Болото, пойма | 0.075 | 0.331 | 0.677 |

где `dNBR = NBR_до − NBR_после`, `NBR = (B8A − B12) / (B8A + B12)`.

Проверка на обучающих данных: **внутри истинного контура гари правило угадывает
класс в 92.5 % пикселей**, а со сглаживанием каналов окном 3×3 — в 93.3 %.
Ошибки приходятся почти исключительно на соседний класс, то есть на границы
порогов, а не на систематическое расхождение.

Вне контура то же правило бесполезно: 9.7 млн фоновых пикселей оно относит к
гари. Причина ясна из состава покрова — 93 % гари приходится на травы и пашню, а
убранное или вспаханное поле спектрально похоже на гарь.

Отсюда вывод: эталон равен контуру гари, раскрашенному формулой, и вся
сложность задачи сосредоточена в контуре. Если контур найден идеально, а
степень считается правилом, верхняя оценка составляет `mIoU_sev ≈ 0.872`.

Поэтому решение двухэтапное, что и отражено в составе весов:

1. **Первый этап** — бинарная модель контура гари, пять моделей на фолдах
   перекрёстной проверки, 60 признаков. Её задача — отличить настоящую гарь от
   уборки, вспашки, засухи и облаков.
2. **Второй этап** — уточнение на 70 признаках, вероятно с использованием
   выходов первого этапа.
3. **Степень внутри контура** — правило порогов по типу покрова, обучения не
   требует.

Обе модели решают бинарную задачу (`binary:logistic`), многоклассовой модели
среди переданных весов нет, что согласуется с этим замыслом.

## Чего не хватает для расчёта предсказаний

Переданы только веса. Для применения моделей необходимо:

1. **`features.json`** — имена и порядок 60 признаков первого этапа и 70
   признаков второго. В самих файлах весов имена не сохранены
   (`feature_names` пуст), поэтому восстановить состав признаков из них
   невозможно. Без этого файла подать данные в модель нельзя: порядок столбцов
   определить неоткуда.
2. **`config.json`** — пороги вероятности, правила объединения пяти моделей
   первого этапа, связь первого этапа со вторым, параметры последующей обработки.
3. **Код расчёта признаков** — как именно считаются 60 и 70 значений из каналов
   Sentinel-2, Sentinel-1, рельефа и типа покрова: размеры окон, состав
   индексов, обработка облачности по слою SCL.
4. **Таблица предсказаний** для тестовых чипов либо подтверждение, что её нужно
   рассчитывать этим модулем.

До получения этих файлов итоговый ответ собирается только по модулю AF, а строки
BS берутся из шаблона пустыми — для этого в сборщике предусмотрен явный
параметр `--fill-from-sample`.

## Данные

224 обучающих чипа и 89 тестовых, размер 512×512 на сетке 20 метров, то есть
10.2 × 10.2 км на чип.

| Класс | Пикселей | Доля |
|---|---|---|
| 0 — не горело | 52 811 255 | 89.94 % |
| 1 — слабое | 2 362 871 | 4.02 % |
| 2 — среднее | 2 192 271 | 3.73 % |
| 3 — сильное | 1 353 859 | 2.31 % |

Гарь занимает около 10 % площади, внутри неё классы распределены равномернее.
Идентификатор пожара заполнен, по одному чипу на пожар, чипы территориально не
пересекаются — поэтому группировка по чипу даёт честную проверку без утечки.

Отдельная сложность: по слою SCL снимка «после» облаками и тенями закрыто
8.9 млн пикселей, и 4.9 % из них размечены как гарь. Обнуление всех облачных
пикселей при последующей обработке эти участки теряет, а из оценки облачность
не исключается.
