# Модуль AF: отчёт об экспериментах

Детекция активного горения по AF-чипам VIIRS. Документ описывает путь от первого
бейзлайна до финального решения: как изучали данные, какие гипотезы выдвигали,
что подтвердилось, что нет и почему.

## Итог в одной таблице

| этап | подход | F1_af |
|---|---|---|
| 1 | YOLO-детекция, бейзлайн | 0.4176 |
| 1a | YOLO + аугментации | 0.3426 |
| — | потолок любой box-детекции (оракул) | 0.7892 |
| 2 | порог `I4 > 330 K`, без обучения | 0.8512 |
| 3 | попиксельный LightGBM, 38 признаков | 0.9287 |
| 4 | **+ факелы из FIRMS как трудные негативы** | **0.9345** |

Все числа, кроме этапа 1, получены на 5-фолдовой кросс-валидации с блокировкой
по территории, `seed = 42`. Этап 1 — отложенная выборка с той же блокировкой.

---

## 1. Постановка

**Вход:** AF-чип 256×256 пикселей на сетке 375 м (96×96 км) — каналы VIIRS I1–I5
и вспомогательные слои.

**Выход:** бинарная маска, 1 — пиксель природного горения, 0 — всё остальное,
включая техногенные термоаномалии (факелы, промплощадки).

**Метрика:** `Score = 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev`. Наша доля —
`F1_af`: попиксельный F1 с микро-усреднением. TP, FP и FN суммируются по всем
чипам в общий пул, F1 берётся от сумм.

Два следствия, определившие работу:

- метрика **пиксельная** — важно, совпадает ли каждый пиксель, а не найден ли
  «объект»;
- класс крайне редкий, поэтому precision хрупок: лишняя тысяча ложных пикселей
  на весь пул заметно роняет F1.

## 2. EDA

### 2.1 Структура данных

420 обучающих чипов, 180 тестовых. На каждый чип три GeoTIFF.

**Первая находка — имена файлов не соответствуют содержимому.** Файл
`*_VIIRS_I1-I5.tif` содержит не 5 каналов, а 8; файл `*_AUX.tif` — не 8, а 5.
Реальный состав взят из тега `GDAL_METADATA`:

| файл | каналы |
|---|---|
| VIIRS | I1, I2, I3, I4, I5, solar_zenith, sensor_zenith, valid |
| AUX | landcover, dem, t2m, rh2m, wind_speed |
| MASK | active_fire, nodata = 255 |

→ **Решение:** каналы всегда читаются по описаниям из метаданных, а не по позиции.

**Вторая находка — NaN есть там, где `valid = 1`.** На контрольном чипе канал
`valid` равен единице по всей площади, но в I1–I5 3856 пропусков.

→ **Решение:** NaN обрабатываются явно, маска `valid` — дополнительный фильтр.

Контроль корректности чтения: сумма горящих пикселей по всем маскам — **9 725**,
что совпадает с `meta.csv` и с числом в постановке.

### 2.2 Метаданные

Из 26 колонок `meta.csv` заполнены 12. Пусты во всех 420 строках, среди прочих:
`fire_event_id`, `region`, `landcover_top`.

Критична первая: постановка обещает, что «чипы одного пожара целиком лежат в одной
выборке», но ключа для этого нет.

→ **Решение:** валидацию пришлось строить на прокси-группах (раздел 4).

### 2.3 Баланс классов

| показатель | значение |
|---|---|
| чипов с огнём / без | 296 / 124 |
| пикселей горения | 9 725 |
| **доля от площади** | **0.035 %** |
| пикселей горения на положительном чипе | медиана 21, максимум 243 |
| ночных пролётов | 127 чипов, из них 89 с огнём |
| месяцы съёмки | только апрель–октябрь, **зимы нет вообще** |

→ **Решение:** негативы при обучении прореживаются; порог уверенности подбирается
по пулу пикселей, а не берётся по умолчанию.

### 2.4 Геометрия объектов — решающая находка

Маски разложены на связные компоненты (8-связность):

| показатель | значение |
|---|---|
| объектов всего | 3 287 |
| размер компоненты | **медиана 2 пикселя** |
| компонент ровно в 1 пиксель | **1 337 (41 %)** |
| медианный bbox | **1×1** |
| bbox не крупнее 2×2 | 76 % |

Объекты — это единичные пиксели. Это определило судьбу первого подхода (раздел 3).

### 2.5 Разделимость сигнала

Физика: очаг 600–1200 K смещает максимум излучения в средний ИК, поэтому в канале
I4 (3.74 мкм) контраст к фону на два порядка выше, чем в тепловом I5 (11.45 мкм).

На контрольном чипе:

| признак | огонь, медиана | фон, 99-й перцентиль |
|---|---|---|
| I4 | 341.0 K | 312.5 K |
| **I4 − I5** | **39.7 K** | **8.8 K** |

Разность каналов разделяет классы заметно лучше абсолютной температуры.

→ **Решение:** `I4 − I5` вынесена в отдельный признак и во все контекстные
статистики.

## 3. Детекция: почему от неё отказались

### 3.1 Бейзлайн на YOLO

Первый бейзлайн — `yolo11n`, обученный только на выданных чипах, без аугментаций.

Решения, вытекавшие из EDA:

- **апскейл ×4 до 1024×1024** методом ближайшего соседа. Медианный объект 1×1 px,
  а голова P3 работает со stride 8 — без апскейла цели в 64 раза мельче ячейки
  предсказаний. Билинейная интерполяция смазала бы горячий пиксель и занизила пик I4;
- **рендер 3 каналов по физике:** R = I4, G = I4 − I5, B = I3 (блик как антипризнак);
- **нормировка глобальная, фиксированными порогами** (I4: 270–367 K, где 367 K —
  насыщение сенсора). Нормировка по каждому чипу растянула бы шум на чипах без огня.

Метрика — не `mAP50`, который печатает ultralytics, а та же попиксельная `F1_af`:
боксы заливаются в маску 256×256.

**Результат: F1 = 0.4176** (precision 0.28, recall 0.79).

### 3.2 Гипотеза: аугментации помогут

Проверено: геометрия (повороты, сдвиги, отражения) плюс умеренный сдвиг
яркости и цвета.

**Результат: F1 = 0.3426, хуже бейзлайна на 0.075.** Гипотеза отвергнута.

Причина: каналы — это физические величины. Яркость в канале R есть яркостная
температура в кельвинах, и её сдвиг означает «пожар стал холоднее» — модель
учится на физически невозможных примерах.

### 3.3 Потолок подхода

Чтобы понять, стоит ли дальше улучшать детекцию, посчитан оракул: берём
**идеальные** боксы из эталона — все объекты найдены, координаты точны — и
заливаем их целиком.

| precision | recall | F1 |
|---|---|---|
| 0.652 | 1.000 | **0.789** |

**0.789 — потолок любого детектора на этой задаче.** Прямоугольник вокруг
диагональной цепочки из трёх пикселей неизбежно захватывает шесть фоновых.
Это свойство подхода, а не качества модели; тюнинг его не сдвигает.

Косвенное подтверждение на тесте: YOLO предсказал 51 горящий пиксель на чип
против 23 в эталоне обучающей части — переразметка вдвое, ровно тот избыток фона.

### 3.4 Проверка «а нужна ли модель вообще»

Одна строка кода без обучения — порог по каналу I4:

| правило | F1 |
|---|---|
| I4 > 325 | 0.4400 |
| **I4 > 330** | **0.8815** на отложенной выборке, 0.8512 на всех 420 чипах |
| I4 > 335 | 0.7743 |

**Порог без обучения обгоняет обученный YOLO вдвое и перепрыгивает потолок
детекции.** Вывод: эталон организаторов построен пороговым алгоритмом по тем же
каналам VIIRS, что нам выдали, — что согласуется с постановкой, где термоточки
определяются контекстным алгоритмом.

→ **Решение:** переход к попиксельной классификации. Каждый пиксель — отдельный
пример, боксов нет, потолка нет.

## 4. Валидация

### 4.1 Прокси-группы

Организаторы режут public/private «одновременно по территории и по времени».
Их ключ `fire_event_id` пуст, поэтому введены два прокси:

- **тайл** `(epsg, x_min, y_min)` — территория;
- **сцена** `(acq_datetime, satellite)` — один пролёт, то есть один пожар.

Территория важнее: постоянные термоаномалии привязаны к местности, и при случайном
сплите модель запоминала бы положение факелов — ровно тех объектов, которые
обязана отфильтровывать.

### 4.2 Одновременная развязка невозможна — доказано

Гипотеза: можно развести и тайлы, и сцены одновременно.

Проверено построением двудольного графа «тайл — сцена» (70 + 78 вершин, ребро на
каждый чип). **Граф — одна компонента связности на все 420 чипов.** Каждая сцена
покрывает несколько тайлов, каждый тайл снят в нескольких сценах. Любой сплит с
обеими развязанными осями обязан выбрасывать данные.

Замер вариантов:

| схема | train | val | выброшено |
|---|---|---|---|
| тайл + сезон 2024 | 286 | 6 | 128 |
| тайл + сезоны 2023–2024 | 196 | 37 | 187 |
| **5 фолдов по тайлу** | **все 420 по очереди** | | **0** |

→ **Решение:** рабочая схема — 5 фолдов с блокировкой по тайлу. Строгая двойная
развязка оставлена как контрольная проверка на утечку.

### 4.3 Метрика в коде

`sklearn.metrics.f1_score` по пулу пикселей с `average='binary'`. Это и есть
микро-усреднение по классу «горение».

`average='micro'` неприменим: в бинарной задаче он учитывает оба класса и
превращается в accuracy. Проверено на синтетике: `binary` — 0.4426, `micro` —
0.9993, что совпадает с accuracy. На наших данных это дало бы 0.999 вместо 0.93.

Ранняя версия использовала собственную реализацию; после перехода на sklearn все
числа совпали до четвёртого знака.

## 5. Попиксельная модель

### 5.1 Признаки — 38 на пиксель

| группа | состав | идея |
|---|---|---|
| сырые каналы | I1–I5, углы, valid, landcover, dem, метео | все 13 слоёв |
| разности | `I4 − I5`, `I4/I5`, `I3 − I2` | физика горения и блика |
| **контекстные**, окна 5/11/21 | для I4 и `I4 − I5`: отклонение от локального среднего, z-оценка, локальное СКО | ядро метода |
| морфология | разрыв до локального максимума, минимум, медиана | края очага |

Контекстная группа повторяет логику операционных алгоритмов NASA (VNP14): пиксель
горячий не абсолютно, а **относительно соседей**. Степь в августе в полдень
раскалена сама по себе; пиксель на 40 K выше окружающего фона — очаг в любых
условиях.

### 5.2 Почему бустинг

Эталон по сути набор порогов, а дерево решений — машина для порогов. 420 чипов
мало для нейросети, а бустинг учится за минуты на CPU.

Гипотеза: выбор библиотеки существенен. Проверено на одной схеме валидации с
одним seed:

| модель | F1 | precision | recall |
|---|---|---|---|
| **LightGBM** | **0.9287** | 0.9099 | 0.9483 |
| HistGradientBoosting | 0.9269 | 0.9067 | 0.9479 |
| CatBoost | 0.9246 | 0.9173 | 0.9319 |
| XGBoost | 0.9190 | 0.8957 | 0.9434 |

**Разброс 0.0097 — гипотеза отвергнута.** Качество упирается в признаки, а не в
алгоритм. Выбран LightGBM как лучший и быстрый.

### 5.3 Дисбаланс

В обучение идут все горящие пиксели и 1500 случайных негативов с чипа.

Порог вероятности подбирается по сетке, сгущённой у единицы: из-за дисбаланса
оптимум уезжает к 0.995–0.999, обычный 0.5 разметил бы слишком много.

### 5.4 Проверка на утечку

Три независимых аргумента:

1. **Порог `I4 > 330` не обучается** и даёт 0.8512. У правила без обучения
   утечки быть не может — высокая цифра есть свойство задачи.
2. **Строгая двойная развязка:** тайлы и сцены разведены одновременно, в обучении
   остаётся **27 чипов из 420**, модель даёт **0.8323**. Если бы результат стоял на
   утечке, он рухнул бы здесь.
3. **Группировка** вместо случайного разбиения во всех фолдах.

Разрыв 0.9287 → 0.8323 объясняется объёмом обучения (336 чипов против 27), а не
утечкой.

### 5.5 Гипотеза: кольцевой фон лучше оконного

Идея: окно для оценки фона включает сам пиксель, и горячая точка задирает
собственную оценку. В классических алгоритмах фон берут кольцом с вырезанным
центром.

| признаки | шт | F1 | Δ |
|---|---|---|---|
| окна (исходные) | 38 | 0.9287 | — |
| кольца вместо окон | 38 | 0.9284 | −0.0003 |
| окна + кольца | 56 | 0.9272 | −0.0015 |

**Гипотеза отвергнута.** Окно 21×21 содержит 441 пиксель, и один горячий сдвигает
среднее незначительно; добавочные 18 признаков только добавили шума.

## 6. Внешние данные

### 6.1 Зачем

Постановка прямо требует отделять газовые факелы от пожаров. По одиночному
снимку это невозможно — факел действительно горит. Отличает его **повторяемость**:
срабатывания в одной точке из года в год, **включая зиму**, когда степь не горит.

В выданных данных зимы нет вообще — все 420 чипов в апреле–октябре. Нужен
внешний многолетний архив.

### 6.2 Что взято

| источник | объём |
|---|---|
| NASA FIRMS, VIIRS S-NPP + NOAA-20, 2019–2025 | 1 218 415 детекций после дедупликации, 36 439 зимних |
| OpenStreetMap, промышленные объекты | 35 389 объектов |

Правила разрешают использовать FIRMS для обучения на исторических данных.

**Ограничение:** у тестовых чипов геопривязка скрыта, восстанавливать её
запрещено. Значит внешние данные не могут быть признаком модели — на инференсе
координат нет. Единственный законный путь — использовать их **только при
обучении**.

### 6.3 Диагноз: факелы — реальный источник ошибок

Кандидат в факелы — пиксель, где FIRMS фиксировал зимние детекции минимум в
3 разных года. Сопоставлены с ошибками базовой модели:

| показатель | значение |
|---|---|
| ложных срабатываний | 913 |
| из них на кандидатах в факелы | **107 (11.7 %)** |
| доля таких пикселей в фоне | 0.09 % |
| **обогащение** | **в 134.7 раза** |

11.7 % ошибок приходятся на 0.09 % площади. Это систематика, и она ровно там, где
предсказывала постановка.

Побочная находка: 4.4 % эталонных пикселей горения тоже лежат на местах с
зимними срабатываниями — вероятно, реальные палы вокруг промплощадок. Организаторы
отфильтровали техногенные источники не полностью.

### 6.4 Применение: трудные негативы

Факельные пиксели подаются в обучение как негативы — чаще и с повышенным весом,
чтобы модель научилась отбивать их по самим каналам чипа. Инференсу внешние
данные не нужны.

| вес | доля факелов среди негативов | F1 | Δ |
|---|---|---|---|
| — | — | 0.9287 | — |
| 1 | 0.15 | 0.9337 | +0.0050 |
| 1 | 0.30 | 0.9325 | +0.0038 |
| 3 | 0.15 | 0.9328 | +0.0041 |
| 3 | 0.30 | 0.9326 | +0.0039 |
| **10** | **0.30** | **0.9345** | **+0.0058** |

**Все пять вариантов дают прирост +0.004…+0.006.** Эффект устойчивый. Различия
между вариантами — порядка 0.002, на уровне шума сэмплирования; выбран лучший по
замеру.

Неожиданность: прирост пришёл через **recall** (0.948 → 0.968), а не precision.
Научившись уверенно отбивать факелы, модель работает на более низком пороге
(0.999 → 0.995) и подбирает слабые очаги, которые раньше срезались вместе с ними.

### 6.5 OSM: гипотеза отвергнута

Гипотеза: промышленные объекты OSM поймают источники, которых нет в FIRMS.

| слой | площадь фона | доля ошибок | обогащение |
|---|---|---|---|
| FIRMS | 0.09 % | 11.7 % | 134.7x |
| FIRMS ∪ OSM | 0.15 % | 11.8 % | 79.8x |
| **OSM без FIRMS** | 0.06 % | **0.1 %** | **1.8x** |

OSM добавляет 0.1 п.п. покрытия ошибок при обогащении 1.8x — практически
случайно. Если объект реально излучает тепло, FIRMS его уже видит; если нет —
он и детекции не мешает. В модель не взят.

## 8. Финальное решение

- 38 попиксельных признаков: сырые каналы, разности, контекстные статистики в
  окнах 5/11/21, морфология;
- LightGBM, 500 деревьев, `seed = 42`;
- 1500 негативов на чип, из них 30 % — кандидаты в факелы по FIRMS с весом 10;
- порог вероятности подобран по кросс-валидации.

**F1_af = 0.9345** на 5-фолдовой кросс-валидации с блокировкой по территории.
Рост относительно первого бейзлайна — в 2.24 раза.

## 9. Ограничения

1. **Факелы учтены только косвенно.** Модель научилась лучше их отбивать, но
   карты факелов на инференсе нет и быть не может — геопривязка теста скрыта.
2. **Локальная валидация слегка оптимистична.** Сцены между фолдами пересекаются;
   на строгой развязке (правда, с 27 чипами в обучении) — 0.8323.
3. **Модель данными не насыщена:** разрыв между 336 и 27 обучающими чипами —
   0.10 F1. Главный резерв — расширение выборки.
4. **Общий порог для дня и ночи**, хотя `solar_zenith` в признаках есть.
