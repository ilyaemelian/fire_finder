# Модуль AF — детекция активного горения

Полное описание модуля: постановка, изучение данных, путь решения с проверенными
и отвергнутыми гипотезами, устройство признаков, схема проверки качества, состав
файлов и порядок запуска.

**Итог: `F1_af = 0.9345`** на пятифолдовой перекрёстной проверке с блокировкой по
территории, `precision` 0.9032, `recall` 0.9681.

---

## 1. Постановка

**Вход:** чип 256×256 пикселей на сетке 375 м (96×96 км) — каналы VIIRS I1–I5 и
вспомогательные слои.

**Выход:** бинарная матрица, 1 — пиксель природного горения, 0 — всё остальное,
включая техногенные термоаномалии: газовые факелы и промышленные площадки.

**Метрика:** `Score = 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev`. Доля этого
модуля — `F1_af`: попиксельный F1 с микроусреднением, где истинно положительные,
ложно положительные и ложно отрицательные суммируются по всем чипам в общий пул,
а F1 берётся от сумм.

Два следствия определили всю работу. Метрика **попиксельная** — важно совпадение
каждого пикселя, а не факт обнаружения объекта. Класс **крайне редкий**, поэтому
точность хрупка: лишняя тысяча ложных пикселей на весь пул заметно снижает F1.

## 2. Изучение данных

### 2.1 Структура

420 обучающих чипов, 180 тестовых, по три файла GeoTIFF на чип.

**Первая находка: имена файлов не соответствуют содержимому.** Файл
`*_VIIRS_I1-I5.tif` содержит не пять каналов, а восемь; файл `*_AUX.tif` — не
восемь, а пять. Истинный состав взят из тега `GDAL_METADATA`:

| Файл | Каналы |
|---|---|
| VIIRS | I1, I2, I3, I4, I5, solar_zenith, sensor_zenith, valid |
| AUX | landcover, dem, t2m, rh2m, wind_speed |
| MASK | active_fire, признак отсутствия данных 255 |

Отсюда решение: **каналы всегда читаются по текстовым описаниям из метаданных, а
не по порядковому номеру.**

**Вторая находка: пропуски есть там, где канал достоверности равен единице.** На
контрольном чипе `valid` равен единице по всей площади, но в каналах I1–I5
обнаружено 3856 пропусков. Отсюда: пропуски обрабатываются явно, а маска `valid`
служит дополнительным фильтром, а не единственным.

Контроль корректности чтения: сумма горящих пикселей по всем эталонным маскам
равна **9725**, что совпадает и с `meta.csv`, и с числом в постановке.

### 2.2 Метаданные

Из 26 столбцов `meta.csv` заполнены 12. Пусты во всех 420 строках, среди прочих,
`fire_event_id`, `region`, `landcover_top`.

Критичен первый: постановка обещает, что чипы одного пожара целиком попадают в
одну выборку, но ключа для такой группировки нет. Проверку качества пришлось
строить на косвенных группах — раздел 4.

### 2.3 Баланс классов

| Показатель | Значение |
|---|---|
| Чипов с огнём и без | 296 и 124 |
| Пикселей горения | 9725 |
| **Доля от площади** | **0.035 %** |
| Пикселей горения на положительном чипе | медиана 21, максимум 243 |
| Ночных пролётов | 127 чипов, из них 89 с огнём |
| Месяцы съёмки | только апрель–октябрь, **зимы нет вообще** |

Отсюда: фоновые пиксели при обучении прореживаются, а порог уверенности
подбирается по пулу пикселей, а не берётся стандартным.

### 2.4 Геометрия объектов — решающая находка

Эталонные матрицы разложены на связные компоненты при восьмисвязности:

| Показатель | Значение |
|---|---|
| Объектов всего | 3287 |
| Размер компоненты | **медиана 2 пикселя** |
| Компонент ровно в один пиксель | **1337, то есть 41 %** |
| Медианный описывающий прямоугольник | **1×1** |
| Прямоугольник не крупнее 2×2 | 76 % |

Объекты — это единичные пиксели. Этот факт предопределил отказ от детекции,
раздел 3.

### 2.5 Разделимость сигнала

Физическое основание: очаг температурой 600–1200 K смещает максимум излучения в
средний инфракрасный диапазон, поэтому в канале I4 (3.74 мкм) контраст к фону на
два порядка выше, чем в тепловом I5 (11.45 мкм).

На контрольном чипе:

| Признак | Огонь, медиана | Фон, 99-й процентиль |
|---|---|---|
| I4 | 341.0 K | 312.5 K |
| **I4 − I5** | **39.7 K** | **8.8 K** |

Разность каналов разделяет классы заметно лучше абсолютной температуры, поэтому
она вынесена в отдельный признак и во все контекстные статистики.

## 3. Путь решения

| Этап | Подход | `F1_af` |
|---|---|---|
| 1 | Детекция YOLO11n, первая версия | 0.4176 |
| 1a | YOLO с дополнениями обучающей выборки | 0.3426 |
| — | Потолок любой детекции по идеальной разметке | 0.7892 |
| 2 | Пороговое правило `I4 > 330 K`, без обучения | 0.8512 |
| 3 | Попиксельный LightGBM, 38 признаков | 0.9287 |
| 4 | **То же плюс факелы как трудные негативы** | **0.9345** |

### 3.1 Почему отказались от детекции

Первая версия — `yolo11n`, обученная только на выданных чипах. Из изучения данных
вытекали решения: увеличение в четыре раза до 1024×1024 методом ближайшего соседа
(медианный объект 1×1 пиксель, а голова сети работает с шагом 8, то есть без
увеличения цели в 64 раза мельче ячейки предсказаний; сглаживающая интерполяция
смазала бы горячий пиксель и занизила пик I4); трёхканальное изображение по
физике: красный — I4, зелёный — `I4 − I5`, синий — I3 как признак блика;
нормировка глобальная фиксированными порогами, поскольку нормировка по каждому
чипу растянула бы шум на чипах без огня.

Результат — 0.4176. Дополнения обучающей выборки поворотами, сдвигами и
изменением яркости **ухудшили результат** до 0.3426. Причина: каналы суть
физические величины, яркость в красном канале есть яркостная температура в
кельвинах, и её сдвиг означает «пожар стал холоднее» — сеть училась на физически
невозможных примерах.

**Потолок подхода.** Взяты идеальные прямоугольники из эталона — все объекты
найдены, координаты точны — и залиты целиком: точность 0.652, полнота 1.000,
`F1 = 0.789`. Прямоугольник вокруг диагональной цепочки из трёх пикселей
неизбежно захватывает шесть фоновых. Это свойство подхода, а не качества модели.

**Проверка необходимости обучения.** Одна строка без всякого обучения — порог по
каналу I4: при `I4 > 330` получается 0.8512 на всех 420 чипах. Порог без обучения
превосходит и обученный детектор, и его теоретический потолок. Вывод: эталонная
разметка построена пороговым алгоритмом по тем же каналам, что выданы участникам,
и задача сводится к попиксельной классификации, где потолка детекции нет.

## 4. Проверка качества

### 4.1 Косвенные группы

Организаторы делят открытую и закрытую части одновременно по территории и по
времени. Их ключ `fire_event_id` пуст, поэтому введены две косвенные группы:
**тайл** `(epsg, x_min, y_min)` — территория, и **сцена**
`(acq_datetime, satellite)` — один пролёт, то есть один пожар.

Территория важнее: постоянные термоаномалии привязаны к местности, и при
случайном разбиении модель запоминала бы положение факелов — ровно тех объектов,
которые обязана отфильтровывать.

### 4.2 Одновременное разведение невозможно — доказано

Построен двудольный граф «тайл — сцена»: 70 и 78 вершин, ребро на каждый чип.
**Граф оказался одной компонентой связности на все 420 чипов.** Каждая сцена
покрывает несколько тайлов, каждый тайл снят в нескольких сценах, поэтому любое
разбиение с двумя разведёнными осями обязано выбрасывать данные:

| Схема | Обучение | Проверка | Выброшено |
|---|---|---|---|
| Тайл и сезон 2024 | 286 | 6 | 128 |
| Тайл и сезоны 2023–2024 | 196 | 37 | 187 |
| **Пять фолдов по тайлу** | **все 420 по очереди** | | **0** |

Рабочая схема — пять фолдов с блокировкой по тайлу; строгое двойное разведение
оставлено как контрольная проверка на утечку.

### 4.3 Метрика в коде

`sklearn.metrics.f1_score` по пулу пикселей с `average='binary'` — это и есть
микроусреднение по классу «горение». Вариант `average='micro'` неприменим: в
бинарной задаче он учитывает оба класса и вырождается в долю верных ответов.
Проверено на искусственном примере: `binary` даёт 0.4426, `micro` — 0.9993, что
совпадает с долей верных ответов. На наших данных это дало бы 0.999 вместо 0.93.

### 4.4 Проверка на утечку

Три независимых довода. Первый: пороговое правило `I4 > 330` не обучается и даёт
0.8512 — у правила без обучения утечки быть не может, высокий результат есть
свойство задачи. Второй: при строгом двойном разведении в обучении остаётся
**27 чипов из 420**, и модель даёт **0.8323**; если бы результат стоял на утечке,
он рухнул бы здесь. Третий: во всех фолдах применяется группировка, а не
случайное разбиение. Разрыв 0.9287 против 0.8323 объясняется объёмом обучения —
336 чипов против 27, — а не утечкой.

## 5. Признаки: 38 значений на пиксель

| Индексы | Группа | Состав | Идея |
|---|---|---|---|
| 0–12 | Исходные каналы | I1–I5, углы Солнца и сенсора, достоверность, тип покрова, высота, температура, влажность, ветер | все 13 слоёв чипа |
| 13–15 | Разности | `I4 − I5`, `I4 / I5`, `I3 − I2` | физика горения и блика |
| 16–33 | **Контекстные**, окна 5, 11, 21 | для `I4` и `I4 − I5`: отклонение от локального среднего, нормированное отклонение, локальное среднеквадратичное отклонение | ядро метода |
| 34–37 | Морфологические | разрыв до локального максимума для `I4 − I5` и `I4`, минимум 3×3, медиана 5×5 | края очага |

Контекстная группа воспроизводит логику операционных алгоритмов NASA: пиксель
горяч не абсолютно, а **относительно соседей**. Степь в августе в полдень
раскалена сама по себе, но пиксель на 40 K выше окружающего фона есть очаг в
любых условиях.

Порядок признаков сохранён в файле модели и сверяется при каждом применении:
перепутанные столбцы дали бы молча неверный результат.

### 5.1 Выбор алгоритма

Эталон по сути есть набор порогов, а дерево решений — машина для порогов. 420
чипов мало для нейронной сети, а градиентный бустинг обучается за минуты на
центральном процессоре.

Гипотеза о существенности выбора библиотеки **отвергнута**: на одной схеме
проверки и с одним начальным значением генератора LightGBM даёт 0.9287,
HistGradientBoosting 0.9269, CatBoost 0.9246, XGBoost 0.9190. Разброс 0.0097 —
качество упирается в признаки, а не в алгоритм. Выбран LightGBM как лучший и
быстрый.

### 5.2 Дисбаланс и порог

В обучение идут все горящие пиксели и 1500 случайных фоновых с каждого чипа.
Порог вероятности подбирается по сетке, сгущённой у единицы: из-за дисбаланса
оптимум смещается к 0.995–0.999, а обычные 0.5 разметили бы слишком много.

| Порог | Точность | Полнота | F1 |
|---|---|---|---|
| 0.9000 | 0.8636 | 0.9900 | 0.9225 |
| 0.9900 | 0.8926 | 0.9758 | 0.9324 |
| **0.9950** | **0.9032** | **0.9681** | **0.9345** |
| 0.9990 | 0.9216 | 0.9342 | 0.9278 |
| 0.9999 | 0.9498 | 0.8461 | 0.8949 |

### 5.3 Отвергнутая гипотеза: кольцевой фон

Идея: окно для оценки фона включает сам пиксель, и горячая точка задирает
собственную оценку; в классических алгоритмах фон берут кольцом с вырезанным
центром. Проверено: кольца вместо окон дают 0.9284 против 0.9287, окна вместе с
кольцами — 0.9272 при 56 признаках вместо 38. Гипотеза отвергнута: окно 21×21
содержит 441 пиксель, один горячий сдвигает среднее незначительно, а добавочные
18 признаков вносят только шум.

## 6. Внешние данные: газовые факелы

Постановка прямо требует отделять газовые факелы от пожаров. По одиночному снимку
это невозможно: факел действительно горит. Отличает его **повторяемость** —
срабатывания в одной точке из года в год, **включая зиму**, когда степь не горит.
В выданных данных зимы нет вообще.

Взяты архивы NASA FIRMS, приборы VIIRS S-NPP и NOAA-20 за 2019–2025 годы:
1 440 355 записей, после удаления повторов 1 218 415 детекций, из них 36 439
зимних. Правила разрешают использовать FIRMS для обучения на исторических данных.

**Ограничение:** у тестовых чипов геопривязка скрыта, восстанавливать её
запрещено. Значит внешние данные не могут быть признаком модели — на расчёте
предсказаний координат нет. Единственный законный путь — использовать их
**только при обучении**.

Кандидатом в факелы считается пиксель, где FIRMS фиксировал зимние детекции не
менее чем в трёх разных годах; таких пикселей 24 361. Сопоставление с ошибками
базовой модели:

| Показатель | Значение |
|---|---|
| Ложных срабатываний | 913 |
| Из них на кандидатах в факелы | **107, то есть 11.7 %** |
| Доля таких пикселей в фоне | 0.09 % |
| **Обогащение** | **в 134.7 раза** |

11.7 % ошибок приходятся на 0.09 % площади — это систематическая ошибка, и она
ровно там, где предсказывала постановка.

Факельные пиксели подаются в обучение как негативы чаще и с повышенным весом.
Все проверенные сочетания дали устойчивый прирост от 0.004 до 0.006; выбрано
лучшее — вес 10 при доле 30 %, прирост 0.0058. Неожиданность: прирост пришёл
через **полноту** (с 0.948 до 0.968), а не точность. Научившись уверенно отбивать
факелы, модель работает на более низком пороге и подбирает слабые очаги, которые
раньше срезались вместе с ними.

Побочная находка: 4.4 % эталонных пикселей горения тоже лежат на местах с зимними
срабатываниями — вероятно, реальные палы вокруг промышленных площадок.
Организаторы отфильтровали техногенные источники не полностью.

**Отвергнуто:** промышленные объекты OpenStreetMap (35 389 объектов) добавляют
0.1 процентного пункта покрытия ошибок при обогащении в 1.8 раза, то есть
практически случайно. Если объект реально излучает тепло, FIRMS его уже видит.

## 8. Состав модуля

| Путь | Назначение |
|---|---|
| `features.py` | Чтение каналов чипа и расчёт 38 признаков. Единственное описание их состава: им пользуются и расчёт таблицы предсказаний, и веб-приложение |
| `predict.py` | Применение модели к одному чипу: `load_model`, `predict_proba`, `predict_af`, проверка выходной матрицы |
| `inference.py` | Расчёт таблицы предсказаний по всем чипам шаблона и запись `results/af_submission.csv`; функция `run` — вход для пайплайна |
| `train.py` | Воспроизводимое обучение LightGBM, кросс-валидация, подбор порога и запись нового артефакта |
| `artifacts/model.pkl` | Модель, порог вероятности, порядок признаков, размеры окон, начальное значение генератора |
| `artifacts/manifest.json` | Паспорт: гиперпараметры, метрики, контрольные суммы, что именно проверено |
| `data/firms/*.csv.gz` | Архивы NASA FIRMS за 2019–2025 годы. Нужны только при обучении |
| `notebooks/pipeline.ipynb` | Тетрадь обучения и проверки качества, пять ячеек, с выводами выполнения |
| `research_af.ipynb` | Тетрадь исследования модуля: наблюдения в данных, проверенные гипотезы и принятые решения |
| `results/af_submission.csv` | Создаётся текущим запуском инференса и не хранится как заранее подготовленный ответ |

`research_af.ipynb` — исследовательская часть модуля, оцениваемая по разделу
«Отчёт и исследование». Изложение построено как «наблюдение в данных — гипотеза
— решение, принятое в `notebooks/pipeline.ipynb`». Разобраны: дисбаланс классов
и доля горящих пикселей, геометрия объектов горения, разделимость сигнала по
каналам I4 и I5, обоснование отказа от детекции объектов в пользу попиксельной
классификации, состав 38 признаков, размеры окон контекста 5, 11 и 21, выбор
порога вероятности по F1, схема территориальной валидации и отбор техногенных
термоаномалий по архивам NASA FIRMS в качестве отрицательных примеров
(`NEG_PER_CHIP`, `FLARE_SHARE`, `FLARE_WEIGHT`).

Корень репозитория тетрадь определяет поиском каталога `data/train/af` от
текущего каталога вверх; абсолютных путей с машины разработчика в ней нет.
Архивы FIRMS читаются из `data/firms/`. Для выполнения нужны `matplotlib`,
`pandas` и `scipy`.

### Тетрадь обучения

Пять ячеек, выполняются по порядку. Нулевая — настройки: пути, размеры окон,
число фоновых пикселей, гиперпараметры, сетка порогов, фиксация случайности
`SEED = 42`. Первая — признаки: каждый пиксель превращается в 38 чисел, признаки
считаются для всех 420 чипов и держатся в памяти вместе с эталонными матрицами.
Вторая — карта газовых факелов по архивам FIRMS, координаты используются только
здесь. Третья — пять фолдов проверки и подбор порога. Четвёртая — обучение
итоговой модели на всех 420 чипах, сохранение `model.pkl`, расчёт предсказаний по
тестовым чипам и запись таблицы; перед этим кодирование проверяется полным
круговым преобразованием на всех эталонных матрицах.

## 9. Запуск

```python
from models.active_fire import WEIGHTS, load_model, predict_af

model = load_model(WEIGHTS)
mask = predict_af(path_to_chip, model)   # uint8, (256, 256), значения 0 и 1
```

Расчёт по всем тестовым чипам:

```powershell
.venv-af\Scripts\python.exe -m models.active_fire.inference --data-dir <каталог теста>
```

Обучение с записью новых весов отдельно от финального артефакта:

```powershell
.venv-af\Scripts\python.exe -m models.active_fire.train --data-dir data/train --output-dir outputs/training/active_fire
```

Полный пайплайн — проверка среды и контрольной суммы весов, расчёт и сразу файл
ответа `outputs/submission/submission_af.csv` по официальному шаблону:

```powershell
.venv-af\Scripts\python.exe -m scripts.run_af_pipeline --data-dir <каталог теста>
```

Ожидаемая структура каталога: `sample_submission.csv` и `af/viirs`, `af/aux` с
файлами `<chip_id>_VIIRS_I1-I5.tif` и `<chip_id>_AUX.tif`. Путь к чипу задаётся
тремя способами: каталог с одной парой файлов, префикс `<каталог>/<chip_id>` или
корень с подкаталогами `viirs` и `aux`.

На проверенной машине полный AF-инференс занял около 72 секунд на 180 тестовых
чипов. Таблица проверяется по правилам конкурса
до записи. Зависимости — `requirements-af.txt`, отдельная среда `.venv-af`.

### Особенность Windows

В Windows `AUX` — зарезервированное имя устройства, поэтому каталог `af/aux` там
создать невозможно: распаковка завершится ошибкой либо каталог будет
переименован. Сами файлы `<chip_id>_AUX.tif` допустимы, ограничение касается
только имени каталога. Поэтому принимается раскладка без подкаталогов: оба файла
чипа лежат рядом, и путь указывается через `--data-dir`. Второй вариант —
выполнять расчёт в подсистеме Linux.

## 10. Воспроизводимость и что проверено

`SEED = 42` для `random`, `numpy`, `PYTHONHASHSEED` и LightGBM. Разбиение
детерминировано. Признаки не зависят от содержимого других чипов и одинаково
считаются при обучении и при расчёте предсказаний.

Проверено при интеграции: порядок признаков совпадает с сохранённым в модели;
модель загружается и полное применение к искусственному чипу VIIRS возвращает
бинарную матрицу 256×256 типа uint8; таблица предсказаний прошла проверку по
правилам конкурса — 180 уникальных строк, 131 непустая матрица, 3877
положительных пикселей, нарушений формата и кодирования нет.

Командный путь обучения проверен smoke-запуском на реальных обучающих чипах:
чтение данных, обучение фолдов, подбор порога и сохранение `model.pkl` выполняются
без ручной правки кода. Полный пересчёт исходного артефакта требует запуска на
всех 420 чипах; приведённые итоговые метрики относятся к авторскому полному
эксперименту, а не к smoke-проверке.

## 11. Ограничения

1. Карты факелов при расчёте предсказаний нет и быть не может: геопривязка
   тестовых чипов скрыта. Модель отбивает их только по содержимому снимка.
2. Оценка слегка оптимистична: сцены между фолдами пересекаются. При строгом
   разведении территории и времени результат составляет 0.8323, правда при 27
   чипах в обучении.
3. Модель не насыщена данными: разрыв между 336 и 27 обучающими чипами равен 0.10
   по `F1_af`. Основной резерв — расширение выборки.
4. Порог вероятности общий для дневных и ночных пролётов, хотя угол Солнца среди
   признаков есть.
