# Контур — система мониторинга природных пожаров

Решение задачи дистанционного обнаружения природных пожаров по данным спутниковой
съёмки. Система определяет пиксели активного горения по снимкам VIIRS, оценивает
степень поражения пройденной огнём территории по снимкам Sentinel-2 и предоставляет
пространственно-временной анализ результатов через картографический веб-интерфейс.

## Архитектура

Система состоит из трёх независимых составляющих. Модели не вызывают код друг
друга и не обращаются к коду веб-приложения; обмен данными выполняется только
через файлы.

```text
                    ┌───────────────────────────┐
   VIIRS ──────────►│ models/active_fire   (AF) │─► results/active_fire_yolo.csv ──┐
   (I3, I4, I5)     └───────────────────────────┘                                  │
                    ┌───────────────────────────┐                                  ├─► scripts/collect_results.py
   Sentinel-2 ─────►│ models/burn_severity (BS) │─► results/burn_severity_*.csv ───┘             │
   (до и после)     └───────────────────────────┘                                                ▼
                    ┌───────────────────────────┐                             outputs/submission/submission.csv
   .npy + метаданные│  src/ + frontend/  (веб)  │─► карта, площади, выгрузки
   ────────────────►└───────────────────────────┘
```

| Составляющая | Каталог | Вход | Выход | Среда |
|---|---|---|---|---|
| Модель AF — активное горение | `models/active_fire/` | снимок VIIRS в формате GeoTIFF | матрица 256×256, тип `uint8`, классы 0/1 | `.venv-af` |
| Модель BS — степень поражения | `models/burn_severity/` | пара снимков Sentinel-2 до и после пожара | матрица 512×512, тип `uint8`, классы 0–3 | `.venv-bs` |
| Веб-приложение | `src/`, `frontend/` | две матрицы `.npy` и файл метаданных | карта, площади в гектарах, выгрузки | `.venv` |

Каталог `models/common/` содержит общий для обеих моделей код обмена: кодирование
матриц методом группового кодирования длин серий (RLE) и правила формирования и
проверки таблиц предсказаний.

## Установка и запуск

Проверенная среда: Windows, Python 3.13.3, Node.js 22.23.1. Все команды
выполняются из корня репозитория.

| Действие | Команда |
|---|---|
| Среда веб-приложения | `python -m venv .venv` и `.venv/Scripts/python.exe -m pip install -r requirements.txt` |
| Среда модели AF | `python -m venv .venv-af` и `.venv-af/Scripts/python.exe -m pip install -r requirements-af.txt` |
| Среда модели BS | `python -m venv .venv-bs` и `.venv-bs/Scripts/python.exe -m pip install -r requirements-bs.txt` |
| Сборка интерфейса | `npm --prefix frontend ci` и `npm --prefix frontend run build` |
| Демонстрационный набор | `.venv/Scripts/python.exe -m scripts.seed_demo` |
| Запуск сервера | `.venv/Scripts/python.exe -m uvicorn src.service.main:app --host 127.0.0.1 --port 8000` |
| Расчёт предсказаний AF | `.venv-af/Scripts/python.exe -m models.active_fire.run_inference --data-dir <каталог> --sample <шаблон>` |
| Обучение BS | `.venv-bs/Scripts/python.exe -m models.burn_severity.train --data-dir <каталог> --limit 30` |
| Расчёт предсказаний BS | `.venv-bs/Scripts/python.exe -m models.burn_severity.run_inference --data-dir <каталог> --sample <шаблон>` |
| Формирование ответа | `.venv/Scripts/python.exe -m scripts.collect_results --sample data/sample_submission.csv` |
| Проверки | `.venv/Scripts/python.exe -m pytest -q` |

Интерфейс доступен по адресу `http://127.0.0.1:8000`, описание маршрутов —
`http://127.0.0.1:8000/docs`. Каталог хранения данных переопределяется переменной
окружения `FIRE_DATA_DIR`. Три среды разделены намеренно: веб-приложению не нужны
библиотеки глубокого обучения, поэтому оно устанавливается и запускается отдельно.

## Формат данных

Матрицы предсказаний, принимаемые веб-приложением:

| Файл | Размер | Тип | Значения |
|---|---|---|---|
| `active_fire.npy` | 256×256 | `uint8` | 0 — горение отсутствует; 1 — природное горение |
| `burn_severity.npy` | 512×512 | `uint8` | 0 — гарь отсутствует; 1 — слабое, 2 — среднее, 3 — сильное поражение |

Двоичный режим для второй матрицы не предусмотрен. Присутствие всех классов на
конкретном снимке не обязательно: значение 1 всегда означает слабое поражение,
даже при отсутствии значений 2 и 3. Несоответствие размера, типа или множества
классов приводит к отказу без автоматического преобразования.

Вместе с матрицами передаётся файл метаданных. Образец формируется в каталоге
`data/demo-input/` командой `python -m scripts.seed_demo`.

```json
{
  "title": "Название набора",
  "data_mode": "synthetic",
  "source": "Происхождение данных",
  "active_fire": {
    "observation_id": "af-001",
    "crs": "EPSG:32637",
    "transform": [375, 0, 452000, 0, -375, 5148000],
    "model_version": "stub-1",
    "acquisition_datetime": "2025-09-12T10:30:00Z"
  },
  "burn_severity": {
    "observation_id": "bs-001",
    "crs": "EPSG:32637",
    "transform": [20, 0, 494880, 0, -20, 5105120],
    "model_version": "stub-1",
    "date_pre": "2025-08-20",
    "date_post": "2025-09-15"
  }
}
```

Поле `transform` содержит шесть коэффициентов аффинного преобразования a, b, c,
d, e, f: `x = a·(col+0.5) + b·(row+0.5) + c`, `y = d·(col+0.5) + e·(row+0.5) + f`.
Значение `data_mode` разделяет искусственные и действительные данные. Матрицы
двух моделей заданы на разных сетках и не совмещаются по индексам. Матрицы без
координатной привязки и дат для отображения на карте не принимаются. Предельный
размер одной матрицы — 4 МБ, метаданных — 64 КБ; имена передаваемых файлов не
используются как пути на сервере.

Таблица предсказаний для конкурса имеет три столбца: `chip_id`, `class_id`, `rle`.
Кодирование построчное, нумерация пикселей с единицы, формат «начало длина».
Для модели AF на фрагмент приходится одна строка с `class_id = 1`, для модели BS —
три строки с `class_id` 1, 2 и 3; класс 0 в таблицу не входит.

## Модуль AF — активное горение

Модель обнаружения YOLO11n. Входной снимок VIIRS содержит каналы `I3`, `I4`, `I5`
и канал достоверности `valid`, читаемые по текстовым описаниям каналов GeoTIFF, а
не по порядковым номерам. Из них формируется трёхканальное изображение: `I4`
нормируется в диапазоне 270–367 К, разность `I4 − I5` — в диапазоне 0–60 К, `I3` —
в диапазоне 0–0.6. Пиксели с `valid < 0.5` обнуляются. Изображение увеличивается
методом ближайшего соседа в четыре раза до размера 1024×1024, что соответствует
условиям обучения. Предсказанные прямоугольники с достоверностью не ниже 0.5
растеризуются обратно в сетку 256×256.

```python
from models.active_fire import WEIGHTS, load_model, predict_af

model = load_model(WEIGHTS, device="cpu")
mask = predict_af(path_to_geotiff, model)   # uint8, (256, 256), классы 0/1
```

Состояние: весовые коэффициенты загружаются, полный расчёт проверен, таблица
предсказаний на 180 фрагментов корректна — 120 непустых матриц, 9246 положительных
пикселей, нарушений формата не обнаружено. Заявленные автором значения
`F1 = 0.4176`, точность 0.2836, полнота 0.792 независимо не воспроизведены:
тетрадь сохранена без результатов выполнения, обучающая и проверочная выборки не
переданы. В паспорте модели эти значения помечены как заявленные, поле
`training_reproduced` имеет значение `false`.

Отображение конкурсных проверочных матриц на карте невозможно: координаты и даты
проверочной выборки скрыты правилами задачи. Для демонстрации модель применяется
к отдельному разрешённому набору с координатной привязкой.

## Модуль BS — степень поражения

Классификатор CatBoost, функция потерь `MultiClass`, четыре класса. Признаки
рассчитываются попиксельно по каналам B8A (индекс 6) и B12 (индекс 8) снимков
Sentinel-2 до и после пожара:

| Признак | Формула |
|---|---|
| `NBR_pre` | `(B8A_pre − B12_pre) / (B8A_pre + B12_pre + 1e-8)` |
| `NBR_post` | `(B8A_post − B12_post) / (B8A_post + B12_post + 1e-8)` |
| `dNBR` | `NBR_pre − NBR_post` |

Нормализованный индекс гарей NBR построен на контрасте ближнего и коротковолнового
инфракрасного диапазонов: после пожара отражение в ближнем инфракрасном падает, в
коротковолновом растёт, поэтому разность `dNBR` служит основной мерой поражения.
Один фрагмент даёт матрицу признаков размером 262144 × 3.

```python
from models.burn_severity import WEIGHTS, load_model, predict_bs

model = load_model(WEIGHTS)
mask = predict_bs(path_to_chip, model)      # uint8, (512, 512), классы 0/1/2/3
```

Состояние: код обучения и расчёта готов, весовые коэффициенты не получены,
каталог `results/` пуст, оценка качества на проверочной выборке отсутствует.
Индексы каналов и имя файла разметки приняты по документации задачи и на
действительных данных не подтверждены. Модель не использует пространственный
контекст, поэтому границы классов ожидаются шумными; направления улучшения —
статистики по окрестности пикселя, дополнительные спектральные индексы,
радиолокационные каналы и тип подстилающей поверхности.

## Формирование итогового файла ответа

Каждая модель записывает результат в собственный каталог `models/<модуль>/results/`.
Сборщик находит эти файлы самостоятельно, определяет принадлежность к модулю по
префиксу `chip_id`, проверяет каждый файл по отдельности и объединяет строки в
порядке официального шаблона.

```powershell
.venv/Scripts/python.exe -m scripts.collect_results --sample data/sample_submission.csv
```

| Параметр | Назначение |
|---|---|
| `--sample` | Официальный шаблон `sample_submission.csv`; задаёт состав и порядок строк |
| `--output` | Путь результата, по умолчанию `outputs/submission/submission.csv` |
| `--models-root` | Каталог поиска модулей, по умолчанию `models` |
| `--fill-from-sample` | Недостающие строки берутся из шаблона, то есть с пустым полем `rle` |
| `--check <файл>` | Проверка одной таблицы предсказаний без формирования ответа |

Выполняемые проверки: соответствие состава столбцов; отсутствие повторяющихся
пар `chip_id` и `class_id` внутри таблицы; допустимость класса для вида
предсказания (`AF_*` — только 1, `BS_*` — 1, 2 или 3); нахождение всех серий в
границах матрицы; каноничность кодирования; отсутствие пересечения классов
модели BS в пределах одного фрагмента; полное совпадение множества строк с
шаблоном. Любое расхождение прекращает работу с указанием фрагмента.

Таблица модуля может содержать строки обоих видов — например, модуль выдал
полную таблицу по шаблону, где чужие строки оставлены пустыми. Правила
объединения: пустое поле `rle` замещается непустым из другой таблицы; два
одинаковых значения считаются согласованными; два различных непустых значения по
одной паре прекращают работу с указанием обоих файлов. Если в каталоге результатов
модуля несколько таблиц, берётся последняя по времени изменения, остальные
перечисляются в выводе.

Если результат одной из моделей ещё не получен, работа прекращается с сообщением
о числе недостающих строк. Параметр `--fill-from-sample` позволяет получить
ответ, полный по структуре, но заведомо неполный по содержанию: по отсутствующим
фрагментам сдаются пустые матрицы. Проверено на официальном шаблоне: 447 строк
(180 фрагментов AF и 89 фрагментов BS по три класса), порядок строк совпадает с
шаблоном полностью.

## Маршруты HTTP

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | Проверка доступности сервера |
| `GET /api/observations` | Перечень наборов наблюдений, их даты и границы |
| `POST /api/results` | Передача двух матриц и метаданных, возврат `dataset_id` |
| `POST /api/analysis` | Расчёт по параметрам `dataset_id`, `geometry`, `date_from`, `date_to` |
| `POST /api/export/contours` | Выгрузка контуров гарей в формате GeoJSON по `result_id` |
| `POST /api/export/summary` | Выгрузка справки о расчёте в формате JSON по `result_id` |

Расчёт возвращает идентификатор результата, параметры запроса, полноту покрытия,
сводку, точки активного горения и контуры гарей. По сохранённому идентификатору
выгрузка воспроизводит тот же результат после передачи новых наборов. Некорректные
параметры дают код 422, отсутствующий набор или результат — 404, корректный запрос
без обнаружений — код 200 и пустой результат.

Правила расчёта: положительные пиксели модели AF преобразуются в точки обнаружения
и не отождествляются с отдельными пожарами; матрица модели BS векторизуется по
классам 1–3; отбор наблюдений выполняется по дате съёмки для AF и по дате
последующего снимка для BS, границы периода включаются, время приводится к UTC;
контуры отсекаются по заданной области, площадь вычисляется в равновеликой
проекции EPSG:6933 и выражается в гектарах; выгрузка выполняется в системе
координат WGS84. Классы одной матрицы не пересекаются, поэтому общая площадь
равна сумме площадей трёх классов.

## Порядок работы пользователя

1. Открыть карту и выбрать набор наблюдений.
2. Задать период и включить требуемые слои: активное горение и пройденная огнём площадь.
3. Выбрать объект на карте для просмотра даты, версии модели, класса и площади контура.
4. Выделить прямоугольную область указанием двух противоположных углов.
5. Выполнить расчёт и получить общую площадь гари и площади трёх степеней поражения.
6. Выгрузить контуры в формате GeoJSON и справку в формате JSON.

Изменение параметров запроса сбрасывает предыдущую справку. Отсутствие наблюдений
отличается от отсутствия обнаружений; неполнота покрытия области отмечается явно.
Одна передача соответствует одному набору из двух матриц; наборы не объединяются.

## Проверка

Автоматические проверки запускаются командой `python -m pytest -q`.
Покрываются: предобработка и растеризация результата модели AF; расчёт признаков,
устойчивость к нулевой яркости и проверка выходной матрицы модели BS; кодирование
RLE и его каноничность; проверка таблицы предсказаний модуля; определение модуля
по `chip_id`; формирование ответа в порядке шаблона и отказ при неполноте;
проверка матриц и метаданных веб-приложением, геометрия, площади классов, частичная
область, пустой период и соответствие выгрузки справке.

## Состояние готовности и ограничения

Выполнено: веб-приложение с картой, расчётом площадей и выгрузками; модуль AF с
весовыми коэффициентами и проверенной таблицей предсказаний; общий формат обмена
и формирование итогового ответа.

Не выполнено: обучение модели BS и её оценка на проверочной выборке;
воспроизведение обучения модели AF.

Ограничения: полнота покрытия определяется границами переданных матриц, отдельная
матрица достоверности или облачности не передаётся, поэтому покрытие не
подтверждает пригодность каждого исходного пикселя; площадь пикселя модели AF не
отождествляется с фактической площадью горения; восстановление скрытых координат и
дат проверочной выборки запрещено правилами задачи.
