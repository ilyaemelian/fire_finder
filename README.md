# Контур — мониторинг природных пожаров

Решение КосмоХакатона 2026 состоит из двух моделей и веб-сервиса:

- **AF** находит пиксели активного горения по VIIRS;
- **BS** строит контур гари и определяет степень поражения 1–3 по паре снимков;
- **веб-сервис** показывает термоточки и контуры на карте, считает площади и выгружает GeoJSON/JSON.

Финальный файл всегда имеет неизменённый конкурсный формат
`chip_id,class_id,rle`.

Веса обеих моделей входят в репозиторий, поэтому решение запускается без
обучения. Код обучения включён для воспроизводимости и описан в разделе
«Обучение моделей»; для запуска решения он не нужен.

## Быстрый запуск

Команды выполняются из корня проекта. Проверенная версия — Python 3.13.
Пять шагов ниже дают готовый `submission.csv` и заполненную карту в
веб-сервисе.

| Шаг | Что делает |
|---|---|
| 1 | создаёт три изолированные среды |
| 2 | скачивает и распаковывает данные |
| 3 | считает обе модели и формирует `submission.csv` |
| 4 | по желанию переводит расчёт на видеокарту |
| 5 | поднимает веб-сервис и показывает результаты на карте |

### 1. Установить зависимости

```powershell
python bootstrap.py
```

Создаются три изолированные среды: `.venv` для оркестрации и сервиса,
`.venv-af` для AF, `.venv-bs` для BS.

### 2. Отдельно подготовить данные

```powershell
.venv\Scripts\python.exe prepare_data.py --scope all
```

Эта команда скачивает данные с
[Яндекс Диска](https://disk.yandex.ru/d/-rpmevTflbXZQg), проверяет размер и
SHA-256 и распаковывает архивы в `data/train` и `data/test`.

**Загрузка не вызывается из `inference.py`.** Организаторы измеряют время от
старта инференса до появления `submission.csv`, поэтому сетевое скачивание
вынесено в отдельную подготовительную команду.

Можно скачать только нужную часть:

```powershell
.venv\Scripts\python.exe prepare_data.py --scope train
.venv\Scripts\python.exe prepare_data.py --scope test
```

### 3. Запустить инференс

Команда соответствует интерфейсу из постановки:

```powershell
.venv\Scripts\python.exe inference.py --data-dir data/test --output outputs/submission/submission.csv
```

Она не обращается к сети, запускает AF и BS, проверяет результаты и формирует
готовый файл `outputs/submission/submission.csv`. Отдельный запуск сборщика не
нужен.

**Измеренное время полного расчёта: 420 секунд** на процессоре без видеокарты,
Windows, полный тестовый набор — 180 фрагментов AF и 89 фрагментов BS.
Распределение: модуль AF около 70 секунд, остальное приходится на модуль BS, где
7.7 млн пикселей-кандидатов проходят через шесть моделей градиентного бустинга по
800 деревьев, а затем 89 фрагментов обрабатываются свёрточной сетью ResNet34 с
трёхкратным усреднением по отражениям. При наличии видеокарты параметр
`--device cuda` сокращает вторую часть в несколько раз.

Ход расчёта печатается по контрольным точкам: фрагменты AF, признаки BS, фолды
бустинга, фрагменты свёрточной сети. Паузы между сообщениями до полутора минут
на процессоре нормальны и не означают отказа.

### 4. Расчёт на видеокарте

По умолчанию в среду `.venv-bs` ставится сборка `torch` для процессора, и
модуль BS считает на процессоре. Проверить текущее состояние:

```powershell
.venv-bs\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Ответ `2.11.0+cpu False` означает расчёт на процессоре. Чтобы задействовать
видеокарту, та же версия ставится из указателя пакетов с поддержкой CUDA:

```powershell
.venv-bs\Scripts\python.exe -m pip uninstall -y torch
.venv-bs\Scripts\python.exe -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
```

Загружается около 2.5 ГБ. После установки проверка должна дать
`2.11.0+cu128 True`, а расчёт запускается как обычно: параметр `--device auto`
сам выберет видеокарту, `--device cuda` потребует её явно.

Три замечания по версиям:

- Версия CUDA в пакете не обязана совпадать с набором средств разработки CUDA,
  установленным на машине: нужные библиотеки входят в сам пакет. От системы
  требуется только драйвер NVIDIA — для сборки `cu128` не ниже 528.33 в
  Windows. Версию драйвера показывает команда `nvidia-smi`.
- Сборки для CUDA 11.8 существуют только до версии `torch 2.7.1`
  включительно и с этим решением несовместимы: модуль BS обучался и считался
  на `torch 2.11.0`.
- Модуль AF работает на градиентном бустинге и видеокарту не использует;
  ускоряется только модуль BS.

### 5. Запустить веб-сервис и показать на карте результаты моделей

Это полная последовательность от чистой рабочей копии до заполненной карты.
Выполняется из корня проекта, каждая команда — отдельной строкой.

**Шаг 5.1. Подготовить состав фрагментов и их геопривязку.**

```powershell
.venv\Scripts\python.exe -m scripts.build_web_metadata --data-dir data/train --limit-af 20 --limit-bs 6 --output outputs/demo/web_metadata.json --make-sample outputs/demo/sample.csv
```

Команда отбирает 20 фрагментов модуля AF и 6 фрагментов модуля BS, записывает
их систему координат, аффинное преобразование и даты съёмки в
`outputs/demo/web_metadata.json`, а состав строк в конкурсном формате — в
`outputs/demo/sample.csv`. Ожидаемый вывод:

```text
Создан outputs\demo\sample.csv: шаблон состава строк
Создан outputs\demo\web_metadata.json: 26 фрагментов (20 AF, 6 BS)
```

Расчёт ведётся по обучающим фрагментам: геопривязка есть только у них, причина
изложена в разделе «Ограничение выданного тестового набора».

**Шаг 5.2. Рассчитать обе модели по этому составу.**

```powershell
.venv\Scripts\python.exe inference.py --data-dir data/train --sample outputs/demo/sample.csv --output outputs/demo/demo.csv
```

Модуль AF занимает несколько секунд, модуль BS — несколько минут на процессоре.
Результат — `outputs/demo/demo.csv` в неизменённом конкурсном формате
`chip_id,class_id,rle`.

**Шаг 5.3. Поместить результат в хранилище сервиса.**

```powershell
.venv\Scripts\python.exe -m scripts.publish_results --submission outputs/demo/demo.csv --metadata outputs/demo/web_metadata.json --name results --title "Предсказания моделей"
```

Команда соединяет таблицу предсказаний с геопривязкой, раскрывает кодирование
длин серий, переводит контуры в WGS84 и записывает готовый набор наблюдений в
`data/datasets/results.json`. Ожидаемый вывод:

```text
Набор «Предсказания моделей» помещён в ...\data\datasets\results.json
  фрагментов показано: 26
  термоточек: 696
  контуров гари: 2700
  границы набора: 37.311, 44.208 — 47.370, 53.704
  даты наблюдений: 2019-04-01 — 2019-08-31
```

Эти числа — проверка до открытия браузера. Если термоточек и контуров ноль,
на карте будет пусто, и причина в самих масках, а не в сервисе.

**Шаг 5.4. Запустить сервис.**

```powershell
.venv\Scripts\python.exe run.py
```

Открыть `http://127.0.0.1:8000`. Набор уже выбран в списке слева: наборы с
настоящими предсказаниями идут выше учебного синтетического. Загружать файлы
через интерфейс не нужно.

**Шаг 5.5. Что делать в интерфейсе.**

1. Слева в списке «Набор наблюдений» — выбранный набор. Ниже два ползунка
   задают начало и конец интервала наблюдений; по умолчанию взят весь диапазон
   набора.
2. Переключатели «Слои карты» включают и выключают термоточки активного горения
   и контуры пройденной огнём площади. Цвет контура соответствует степени
   поражения: слабая, средняя, сильная.
3. Нажатие на контур открывает его свойства: идентификатор, степень, площадь в
   гектарах, даты пары снимков, версия модели.
4. Кнопка «Выделить область» включает режим выделения: нажатие на карте задаёт
   первый угол прямоугольника, второе нажатие — противоположный. Клавиша Esc
   отменяет.
5. Кнопка «Рассчитать по области» формирует аналитическую справку: суммарная
   площадь гари в гектарах и её распределение по трём степеням поражения,
   число термоточек и число контуров.
6. Кнопки «GeoJSON» и «Справка JSON» выгружают контуры и справку файлами.
   В GeoJSON у каждого контура есть `contour_id`, `severity` и `area_ha`.
   Система координат объявлена в самом файле: поле `crs` содержит
   `urn:ogc:def:crs:OGC:1.3:CRS84`, то есть WGS84, а поле `area_crs` —
   `EPSG:6933`, равновеликую проекцию, в которой считается площадь.

**Шаг 5.6. Тот же результат без интерфейса.**

Описание всех маршрутов — `http://127.0.0.1:8000/docs`. Пример запроса и
выгрузки средствами PowerShell:

```powershell
$sets = Invoke-RestMethod http://127.0.0.1:8000/api/observations
$id = $sets.datasets[0].id
$b = $sets.datasets[0].bounds
$query = @{
  dataset_id = $id
  geometry = @{ type = "Polygon"; coordinates = @(,@(
      @($b[0],$b[1]), @($b[2],$b[1]), @($b[2],$b[3]), @($b[0],$b[3]), @($b[0],$b[1]))) }
  date_from = $sets.datasets[0].date_from
  date_to   = $sets.datasets[0].date_to
} | ConvertTo-Json -Depth 8
$result = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/analysis -ContentType "application/json" -Body $query
$result.summary
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/export/contours -ContentType "application/json" -Body (@{ result_id = $result.result_id } | ConvertTo-Json) -OutFile burned-areas.geojson
```

Маршруты: `GET /api/observations` — список наборов; `POST /api/analysis` —
пространственно-временной запрос, принимает полигон и интервал дат;
`POST /api/export/contours` и `POST /api/export/summary` — выгрузка контуров и
справки; `POST /api/results/submission` — загрузка пары «CSV и геопривязка»,
то же, что шаг 5.3, но по сети.

## Финальная архитектура

### AF — активное горение

LightGBM получает 38 спектральных и контекстных признаков VIIRS. Модель работает
попиксельно, использует фиксированный `seed=42` и выбирает порог по
кросс-валидации. Выход — бинарная маска 256×256.

Исходные веса: `models/active_fire/artifacts/model.pkl`.

### BS — гари и степень поражения

Это финальная схема сокомандника, сохранённая в репозитории:

1. пороги dNBR по типу покрова выделяют кандидатов и задают степень 1–3;
2. пять XGBoost первого прохода оценивают вероятность гари по 60 признакам;
3. второй XGBoost получает ещё 10 признаков пространственного контекста;
4. U-Net ResNet34 обрабатывает 40 каналов и видит форму пятна целиком;
5. вероятности смешиваются: `0.45 · U-Net + 0.55 · XGBoost`;
6. порог `0.4` даёт бинарный контур, степень внутри него берётся из правила dNBR.

Исходные веса лежат только в `models/burn_severity/models/`: пять файлов
`pass1`, `pass2.ubj`, `unet_full_ep25.pt` и `unet_norm.json`.

Две исследовательские тетради:

- `models/active_fire/research_af.ipynb` — исследование модуля активного
  горения. Порядок изложения: наблюдение в данных, гипотеза, принятое решение.
  Разобраны дисбаланс классов и доля горящих пикселей, геометрия объектов
  горения, разделимость сигнала по каналам I4 и I5, обоснование отказа от
  детекции объектов в пользу попиксельной классификации, состав 38 признаков,
  окна контекста 5, 11 и 21, выбор порога вероятности, схема территориальной
  валидации и отбор техногенных термоаномалий по данным NASA FIRMS в качестве
  отрицательных примеров.
- `models/burn_severity/research_bs.ipynb` — исследование модуля картирования
  гарей в том же порядке изложения.

Обе тетради определяют корень репозитория поиском каталога `data/train` от
текущего каталога вверх и не содержат абсолютных путей с машины разработчика.
Для их выполнения нужны `matplotlib` и `pandas`.

Ключевые измеренные результаты BS-исследования:

- формула dNBR правильно задаёт степень внутри истинной гари примерно в 92.5% пикселей;
- сглаживание 3×3 повышает согласие примерно до 93.3%;
- одна формула создаёт много ложных гарей вне истинного контура, поэтому контур предсказывает модель;
- U-Net лучше восстанавливает края, XGBoost лучше работает в ядре пятна;
- смесь дала заявленный автором прирост `+0.018` вклада в итоговую метрику на проверочном фолде.

не менее 12 ГБ свободного места.

## Проверки submission.csv

Перед записью общего файла проверяются:

- полное совпадение `(chip_id, class_id)` с `sample_submission.csv`;
- допустимые классы и размеры масок;
- каноническое построчное RLE с нумерацией от единицы;
- отсутствие NaN, повторов и индексов за границами;
- отсутствие пересечения трёх классов BS.

AF использует класс 1 и размер 256×256. BS использует классы 1–3 и размер
512×512.

## Подключение результатов к веб-сервису: подробности

Порядок действий приведён в разделе «5. Запустить веб-сервис и показать на
карте результаты моделей». Здесь — то, что нужно знать при отклонении от него.

### Почему нужен отдельный файл геопривязки

Конкурсный CSV содержит только `chip_id`, `class_id` и `rle`: ни координат, ни
дат в нём нет. Чтобы показать маски на карте, сервису нужен отдельный файл
`web_metadata.json` с системой координат, аффинным преобразованием и датами
съёмки каждого фрагмента. Структура CSV при этом не меняется.

Состав `chip_id` в CSV и в JSON должен относиться к одному набору данных: имена
обучающих фрагментов начинаются с `AF_tr` и `BS_tr`, тестовых — с `AF_te` и
`BS_te`. Фрагменты, которых нет в JSON, сервис пропускает и сообщает их число;
при полном несовпадении загрузка отклоняется с указанием причины.

### Размер набора

Ограничения числа фрагментов заданы раздельно намеренно. Расчёт AF занимает
доли секунды на фрагмент, расчёт BS — существенно больше, и каждый фрагмент BS
добавляет к матрице признаков порядка 40 МБ. Обучающие фрагменты BS выбраны
вокруг пожаров, поэтому доля пикселей-кандидатов в них выше, чем в тестовых, и
матрица растёт быстрее. Перед сборкой матрицы её размер печатается; при
нехватке памяти добавьте `--work outputs/demo/work` к расчёту BS — признаки
будут храниться на диске.

Ограничения можно опустить: тогда в набор войдут все 644 обучающих фрагмента
(420 AF и 224 BS). Расчёт при этом занимает часы на процессоре, а матрица
признаков BS превышает 8 ГБ, поэтому такой прогон имеет смысл только на
видеокарте и с параметром `--work`. Общий параметр `--limit` задаёт одно и то
же ограничение обоим модулям.

### Параметры построения геопривязки

`scripts.build_web_metadata` читает `meta.csv` рядом с фрагментами: столбцы
`epsg`, `x_min`, `y_max`, `gsd` задают геопривязку, `acq_datetime` — дату
съёмки фрагмента AF, `date_pre` и `date_post` — даты пары снимков фрагмента BS.

| Параметр | Назначение |
|---|---|
| `--data-dir` | каталог с фрагментами и `meta.csv` |
| `--limit-af`, `--limit-bs` | ограничить число фрагментов по модулям раздельно |
| `--limit` | одно ограничение обоим модулям |
| `--kind af` или `--kind bs` | включить только один модуль |
| `--make-sample` | записать шаблон состава строк в конкурсном формате |
| `--submission` | оставить только фрагменты, присутствующие в указанном CSV |
| `--meta` | внешний CSV со сведениями, дополняющий `meta.csv` |
| `--sample` | состав и порядок по готовому шаблону |
| `--output` | путь итогового JSON |

### Геопривязка для готового файла ответа

Если геопривязка тестовых фрагментов известна, она подаётся отдельным файлом, а
метаданные строятся строго по составу уже посчитанного CSV:

```powershell
.venv\Scripts\python.exe -m scripts.build_web_metadata --data-dir data/test --meta test_geo.csv --submission outputs/submission/submission.csv --output outputs/submission/web_metadata.json
.venv\Scripts\python.exe -m scripts.publish_results --submission outputs/submission/submission.csv --metadata outputs/submission/web_metadata.json --name submission --title "Итоговый ответ"
```

Файл `test_geo.csv` должен содержать столбцы `chip_id`, `epsg`, `x_min`,
`y_max`, `gsd`, `acq_datetime` для фрагментов AF и `date_pre`, `date_post` для
фрагментов BS.

### Ограничение выданного тестового набора

Полный `meta.csv` присутствует только у обучающего набора. У тестового набора
столбцы геопривязки и дат из `meta.csv` удалены, а растры записаны без системы
координат и с единичным аффинным преобразованием. Проверено чтением: у
`AF_te_000001_VIIRS_I1-I5.tif` и `BS_te_000001_Sentinel-2_post.tif` поле CRS
пусто, преобразование единичное, тег даты съёмки пуст.

Поэтому показать на карте результаты расчёта по `data/test` без внешних
сведений невозможно: координат этих фрагментов в выданных данных нет.
Ограничение относится к составу выданных данных, а не к сервису: приняв файл со
сведениями, он одинаково обрабатывает обучающие и тестовые фрагменты.

## Обучение моделей

Веса, вошедшие в решение, лежат в репозитории и используются расчётом без
изменений. Код обучения включён для воспроизводимости, но на обычном ноутбуке
не выполняется за разумное время и в инструкцию запуска не входит.

| Модуль | Команда | Требования |
|---|---|---|
| AF | `python -m models.active_fire.train --data-dir data/train --output-dir outputs/training/active_fire` | процессор, 420 фрагментов |
| BS | `python -m models.burn_severity.train --data-dir data/train --output-dir outputs/training/burn_severity/models` | видеокарта; на процессоре время возрастает примерно в тридцать раз |

Обе команды пишут результат в отдельный каталог и отказываются записывать его
поверх `models/active_fire/artifacts` и `models/burn_severity/models`, где
лежат исходные веса; сознательная замена возможна только с флагом `--force`.
Случайные начальные значения закреплены: `seed = 42` для `random`, `numpy`,
`torch`, `PYTHONHASHSEED` и параметра `random_state` моделей; разбиение на
фолды детерминировано и не зависит от порядка файлов в каталоге.

Расчёт заново обученными весами:

```powershell
.venv\Scripts\python.exe inference.py --data-dir data/test --output outputs/submission/retrained.csv --af-model outputs/training/active_fire/artifacts/model.pkl --bs-models outputs/training/burn_severity/models
```

Подробности обучения обоих модулей — в `models/active_fire/README.md` и
`models/burn_severity/README.md`.


Набор проверок охватывает кодирование длин серий и круговое преобразование

## Очистка рабочей копии

Первая команда показывает список без удаления, вторая удаляет:

```powershell
.venv\Scripts\python.exe cleanup.py
.venv\Scripts\python.exe cleanup.py --apply
```

Удаляются отработавшие служебные сценарии, замещённые точки входа, кэш
интерпретатора, кэш и временные каталоги проверок, кэш признаков объёмом около
1.8 ГБ, учебные прогоны обучения объёмом около 450 МБ, промежуточные таблицы
прежней схемы запуска и снимки экрана. Освобождается около 2.3 ГБ.

Исходный код, исследовательские тетради, веса моделей, распакованные данные,
итоговый `outputs/submission/submission.csv` и примеры не затрагиваются.
Скачанные архивы `data/downloads/*.tar` объёмом 3.2 ГБ удаляются отдельным
флагом, поскольку их повторное получение требует загрузки из сети:

```powershell
.venv\Scripts\python.exe cleanup.py --archives --apply
```
