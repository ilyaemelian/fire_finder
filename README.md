# Контур — мониторинг природных пожаров

Решение КосмоХакатона 2026 состоит из двух моделей и веб-сервиса:

- **AF** находит пиксели активного горения по VIIRS;
- **BS** строит контур гари и определяет степень поражения 1–3 по паре снимков;
- **веб-сервис** показывает термоточки и контуры на карте, считает площади и выгружает GeoJSON/JSON.

Финальный файл всегда имеет неизменённый конкурсный формат
`chip_id,class_id,rle`.

## Быстрый запуск

Команды выполняются из корня проекта. Проверенная версия — Python 3.13.

### 1. Установить зависимости

```powershell
python bootstrap.py
```

Создаются три изолированные среды: `.venv` для оркестрации и сервиса,
`.venv-af` для AF, `.venv-bs` для BS.

### 2. Отдельно подготовить данные

```powershell
.venv\Scripts\python.exe prepare_data.py --scope all
```

Эта команда скачивает данные с
[Яндекс Диска](https://disk.yandex.ru/d/-rpmevTflbXZQg), проверяет размер и
SHA-256 и распаковывает архивы в `data/train` и `data/test`.

**Загрузка не вызывается из `inference.py`.** Организаторы измеряют время от
старта инференса до появления `submission.csv`, поэтому сетевое скачивание
вынесено в отдельную подготовительную команду.

Можно скачать только нужную часть:

```powershell
.venv\Scripts\python.exe prepare_data.py --scope train
.venv\Scripts\python.exe prepare_data.py --scope test
```

### 3. Запустить инференс

Команда соответствует интерфейсу из постановки:

```powershell
.venv\Scripts\python.exe inference.py --data-dir data/test --output outputs/submission/submission.csv
```

Она не обращается к сети, запускает AF и BS, проверяет результаты и формирует
готовый файл `outputs/submission/submission.csv`. Отдельный запуск сборщика не
нужен.

**Измеренное время полного расчёта: 420 секунд** на процессоре без видеокарты,
Windows, полный тестовый набор — 180 фрагментов AF и 89 фрагментов BS.
Распределение: модуль AF около 70 секунд, остальное приходится на модуль BS, где
7.7 млн пикселей-кандидатов проходят через шесть моделей градиентного бустинга по
800 деревьев, а затем 89 фрагментов обрабатываются свёрточной сетью ResNet34 с
трёхкратным усреднением по отражениям. При наличии видеокарты параметр
`--device cuda` сокращает вторую часть в несколько раз.

Ход расчёта печатается по контрольным точкам: фрагменты AF, признаки BS, фолды
бустинга, фрагменты свёрточной сети. Паузы между сообщениями до полутора минут
на процессоре нормальны и не означают отказа.

### 4. Воспроизвести обучение

```powershell
.venv\Scripts\python.exe train.py --data-dir data/train --device auto
```

Команда действительно обучает обе части решения:

1. AF LightGBM на 420 обучающих чипах;
2. пять моделей первого прохода BS XGBoost на территориальных фолдах;
3. второй BS XGBoost на контекстных признаках OOF-карты;
4. BS U-Net ResNet34 на 40 каналах, 25 эпох внутри OneCycle-расписания на 60.

Результат сохраняется отдельно от предоставленных весов:

```text
outputs/training/
├── active_fire/artifacts/
└── burn_severity/models/
```

Проверка всего пути обучения на пяти реальных чипах:

```powershell
.venv\Scripts\python.exe train.py --data-dir data/train --smoke
```

Smoke-режим проверяет чтение данных, обучение AF, оба прохода XGBoost, один цикл
U-Net и запись всех артефактов. Его метрики не являются оценкой качества.

Инференс заново обученными весами:

```powershell
.venv\Scripts\python.exe inference.py --data-dir data/test --output outputs/submission/retrained.csv --af-model outputs/training/active_fire/artifacts/model.pkl --bs-models outputs/training/burn_severity/models
```

Полное обучение U-Net рассчитано на CUDA. В режиме `auto` команда использует
GPU при наличии и CPU в остальных случаях. Первый полный запуск скачивает
открытые ImageNet-веса ResNet34; `--encoder-weights none` доступен в модульной
команде обучения BS, но меняет условия эксперимента.

### 5. Запустить веб-сервис

```powershell
.venv\Scripts\python.exe run.py
```

Интерфейс: `http://127.0.0.1:8000`. REST API: `http://127.0.0.1:8000/docs`.

## Финальная архитектура

### AF — активное горение

LightGBM получает 38 спектральных и контекстных признаков VIIRS. Модель работает
попиксельно, использует фиксированный `seed=42` и выбирает порог по
кросс-валидации. Выход — бинарная маска 256×256.

Исходные веса: `models/active_fire/artifacts/model.pkl`.

### BS — гари и степень поражения

Это финальная схема сокомандника, сохранённая в репозитории:

1. пороги dNBR по типу покрова выделяют кандидатов и задают степень 1–3;
2. пять XGBoost первого прохода оценивают вероятность гари по 60 признакам;
3. второй XGBoost получает ещё 10 признаков пространственного контекста;
4. U-Net ResNet34 обрабатывает 40 каналов и видит форму пятна целиком;
5. вероятности смешиваются: `0.45 · U-Net + 0.55 · XGBoost`;
6. порог `0.4` даёт бинарный контур, степень внутри него берётся из правила dNBR.

Исходные веса лежат только в `models/burn_severity/models/`: пять файлов
`pass1`, `pass2.ubj`, `unet_full_ep25.pt` и `unet_norm.json`.

## Исследование — отдельная оцениваемая часть решения

По критериям организаторов раздел **«Отчёт и исследование» даёт до 20 баллов**:
по 4 балла за EDA, baseline, эксперименты, предметные решения и выводы. Это не
вспомогательные заметки, а самостоятельная выполненная часть проекта.

| Критерий | Что исследовано и какое решение принято | Материалы |
|---|---|---|
| EDA и наблюдения | Для AF измерен сильный дисбаланс: около 0.035% горящих пикселей. Для BS измерены баланс фона/гари, распределение степеней, покров, облачность и радарные каналы. Каждый вывод связан с изменением пайплайна | `models/active_fire/README.md`, `models/active_fire/notebooks/pipeline.ipynb`, `models/burn_severity/research_bs.ipynb` |
| Baseline | Разобраны ограничения порогового и CatBoost-baseline: обучение на 30 чипах, отсутствие территориальной валидации, жёсткое обнуление облаков, игнорирование landcover и смешение контура со степенью | `models/burn_severity/research_bs.ipynb`, раздел 7 |
| Эксперименты | Проверены правило степени, сглаживание 3×3, двухпроходный контекст, U-Net и смесь. Зафиксированы `seed=42`, территориальные фолды, единая метрика и параметры финальной смеси | `models/burn_severity/research_bs.ipynb`, `models/burn_severity/IDEAS.md` |
| Инженерные и предметные решения | SCL используется как признак, а не жёсткий фильтр; пороги зависят от покрова; Sentinel-1 помогает отличать вспашку; рельеф и многомасштабный контекст входят в признаки | `models/burn_severity/PIPELINE.md`, `models/burn_severity/core.py` |
| Выводы и развитие | Описаны ложные контуры на пашне, пропуск слабых очагов, ошибки около границ степеней, ограничения одной валидации и план абляций | `models/burn_severity/research_bs.ipynb`, заключительный раздел |

Ключевые измеренные результаты BS-исследования:

- формула dNBR правильно задаёт степень внутри истинной гари примерно в 92.5% пикселей;
- сглаживание 3×3 повышает согласие примерно до 93.3%;
- одна формула создаёт много ложных гарей вне истинного контура, поэтому контур предсказывает модель;
- U-Net лучше восстанавливает края, XGBoost лучше работает в ядре пятна;
- смесь дала заявленный автором прирост `+0.018` вклада в итоговую метрику на проверочном фолде.

## Данные и каталоги

```text
data/
├── downloads/                    # проверенные tar-архивы
├── train/
│   ├── af/
│   └── bs/
├── test/
│   ├── sample_submission.csv
│   ├── af/
│   └── bs/
└── aoi/
```

На Windows каталог `aux` переименовывается загрузчиком в `aux_data`, поскольку
`AUX` — зарезервированное системное имя. Обучение и инференс поддерживают оба
варианта. Пустые каталоги `pre`, `post`, `sar_pre`, `sar_post` не используются;
рабочие файлы находятся в `sentinel2_*` и `sentinel1_*`.

Для архивов, распакованных данных и временных обучающих кэшей желательно иметь
не менее 12 ГБ свободного места.

## Проверки submission.csv

Перед записью общего файла проверяются:

- полное совпадение `(chip_id, class_id)` с `sample_submission.csv`;
- допустимые классы и размеры масок;
- каноническое построчное RLE с нумерацией от единицы;
- отсутствие NaN, повторов и индексов за границами;
- отсутствие пересечения трёх классов BS.

AF использует класс 1 и размер 256×256. BS использует классы 1–3 и размер
512×512.

## Подключение результатов к веб-сервису

Конкурсный CSV намеренно не содержит координат и дат. Для карты нужен отдельный
`web_metadata.json`; структура финального CSV при этом не меняется:

```powershell
.venv\Scripts\python.exe -m scripts.build_web_metadata --data-dir data/test --dates web_dates.csv
```

Затем в интерфейсе используется «Добавить результаты» → «Итоговый CSV».
Пример: `examples/submission_metadata.example.json`.

## Проверка проекта

```powershell
.venv\Scripts\python.exe -m pytest -q
npm.cmd --prefix frontend run build
```

Smoke-обучение проверено на реальных чипах. Контрольные суммы исходных AF- и
BS-весов проверяются перед инференсом. Полный инференс формирует новый CSV и не
использует сохранённые таблицы предсказаний прошлых версий.
